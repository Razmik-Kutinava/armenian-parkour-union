# /trace-bug — сквозной разбор бага (до правок)

Только для багов опасной зоны: оплата и вебхуки (`07`), вход и права (`04`), баллы, степени, взносы (`03`).
Это диагностика, не фикс: код не править, ничего не коммитить.

## Перед стартом

1. Шапка `PROGRESS.md` («Известные проблемы» — баг уже заведён?).
2. Один нужный раздел документа зоны (`03` / `04` / `07`) — по «Оглавлению», не целиком.
3. Узкий поиск по цепочке, не весь код. Цепочка неочевидна после 2–3 файлов — субагент `explore`.

## Вход (заполнить или спросить у владельца)

- **Сценарий:** что делал пользователь.
- **Сбой:** что увидел (экран, лог, статус, сумма).
- **Сущности:** страница, маршрут, таблица, вебхук.

## Анализ (вывод в чат)

1. **Цепочка:** страница → маршрут (`+page.server.ts` / `+server.ts`) → сессия и права → сервис (`src/lib/server/services`) → Drizzle → провайдер / вебхук → обратно на страницу. Где рвётся: `файл:строка` + гипотеза.
2. **Кто это:** один и тот же пользователь и роль на всех шагах? Права проверены на сервере (`04`)?
3. **Вебхуки и журналы:** вебхук дошёл, подпись проверена, повтор не обработан дважды? Статус не откатился назад? Баллы — только записью в журнал (`03`)? Ошибка не проглочена без лога?
4. **Не ломать:** что сломает «быстрый фикс» (соседние сценарии оплаты, начисления, журнал действий).
5. **Как чинить:** минимальный diff + какой тест падает сейчас и станет зелёным.

## Формат ответа

```
Где рвётся: src/…:NN — гипотеза
Затронуто: страница | маршрут | сервис | база | вебхук
Не ломать: …
Файлы (2–7): …
Тест-воспроизведение: …
Проверка: npm run test … | npm run test:e2e …
```
