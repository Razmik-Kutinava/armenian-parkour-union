# /crit-audit — аудит критических ошибок (конечный)

Цель: аудит **сходится** — повторный запуск на том же коммите не даёт новых находок.
Список критичного — K1–K5 в `.cursor/rules/sbr.mdc` (PHASE 3). Журнал — `docs/critical-ledger.md`.
Вызывается в `/review` (шаг 2). Вручную — «проверь на критические».

## Правила

1. **Только K1–K5.** Стиль, «лучше бы», гонки без сценария, UX — в «Не критично» отчёта, на вердикт не влияют. Не поднимать важность, чтобы список не был пустым.
2. **Нет падающего теста — нет находки.** Нужны все три: `файл:строка`, сценарий (кто → какой запрос → что происходит → код K), падающий тест. Не вышло за 2 попытки — `rejected: no-repro`.
3. **Находка → тест навсегда.** RED: `test: CA-NNN … [RED]`, статус `open`. Сказали «чини» — фикс `fix: CA-NNN … [GREEN]`, статус `fixed`; тест остаётся.
4. **Журнал — источник правды.** Находка уже в журнале (`fixed` / `rejected` / `accepted-risk`) — не повторять, кроме случая, когда новый дифф тронул те же строки и есть новый тест.
5. **Scope — только дифф:** `git diff <last_audited_sha>..HEAD -- src drizzle scripts`. Весь код — только по просьбе «полный аудит», одна зона (`04`, `07`, `03`) за проход.
6. Сбой внешнего провайдера (оплата, почта) — не наш баг без доказательства в коде.

## Сделай

1. Прочитать шапку и таблицу журнала. Взять scope по правилу 5.
2. Дифф пустой → гейты → `CLEAN`, стоп. Не искать «ещё что-нибудь».
3. Кандидаты: свой проход по диффу + находки `bugbot` / `security-review` (если из `/review`). Каждый — по правилам 1–4.
4. Гейты: `npm run check`, `npm run lint`, `npm run test`; дифф в опасной зоне — плюс `npm run test:e2e`; CI на HEAD — `gh run list -L 1` (до push — `CI: pending`).
5. Вердикт. **`CLEAN`** — гейты зелёные и нет `open` находок. **`BLOCKED: N`** — N `open` находок с падающим тестом. Мнение без теста вердикт не меняет.
6. Журнал: новые строки, «История аудитов», шапка (`last_audited_sha` = HEAD, дата, вердикт). Коммит `docs: crit-audit …` (вне `/review`).

## Отчёт

```
Вердикт: CLEAN | BLOCKED: N
Scope: <from>..<to> (M файлов)
Гейты: check … · lint … · test … · e2e … | skip · CI …
Новые: CA-NNN K2 src/…:42 — сценарий — тест src/…test.ts (open | fixed | rejected)
Пропущено по журналу: CA-…
Не критично: 1–5 пунктов
```

## Обязательно в конце

`CLEAN` из `/review`: `Next: продолжить /review (шаг 3)`
`CLEAN` вручную: `Next: /review` или работа дальше
`BLOCKED: N`: `Next: /sbr` (чинить CA-…)
