# 06-PUBLIC-SITE: Публичный сайт и личный кабинет

> Отвечает на вопросы: какие страницы и маршруты, что на каждой, откуда берутся данные, какие состояния.
> Правила работы агента — `.cursor/rules/main.mdc`. Структура данных — только `02-DATABASE.md`. Логика — только `03-BUSINESS-RULES.md`. Права — только `04-ROLES-PERMISSIONS.md`. Внешний вид — только `08-DESIGN.md`. Админка — `05-ADMIN-PANEL.md`.

Публичная часть в `src/routes/(site)/`, кабинет в `src/routes/(site)/cabinet/`.

**Для агента:**
- Делать только страницы текущего этапа `09-ROADMAP.md`.
- Условия показа кнопок и состояний не придумывать — брать из `03` и проверять на сервере; интерфейс только отражает результат проверки.
- Данных для блока нет в `02-DATABASE.md` — стоп и вопрос (см. раздел 10).
- Карта, QR-код и подобное — новые библиотеки, только после согласования.

## 1. Общие принципы

1. **Все изменяемые тексты и блоки берутся из БД** (админка), а не из кода. В коде остаются только заголовки интерфейса через файлы переводов (`src/lib/i18n/`).
2. **Языки:** английский по умолчанию без префикса в URL (`/events`), армянский `/hy/events`, русский `/ru/events`. Сначала делается английский, структура маршрутов сразу готова к трём языкам; армянский и русский включаются по мере готовности переводов. Если перевода поля нет, показывается английский.
3. **Рендеринг:** публичные страницы рендерятся на сервере (SSR) для скорости и SEO. Кабинет можно рендерить на сервере с клиентской интерактивностью.
4. **Формы** работают через form actions SvelteKit и без JavaScript (прогрессивное улучшение), валидация на сервере (Zod), ошибки у полей.
5. **Данные** страница получает в `+page.server.ts` через сервисы, а не прямыми запросами в разметке.
6. **Видимость контента:** только `status = published` и `deleted_at is null`; для публикации по дате `published_at <= now`. Черновики видны только админам по ссылке предпросмотра.
7. **Приватность:** контакты и дата рождения участников публично не показываются; несовершеннолетние только по правилам `03`, раздел 13. Закрытые поля не отдаются из `load`, а не просто скрываются в разметке.
8. **Адреса страниц** (slug) человекочитаемые, не меняются после публикации без редиректа.

## 2. Общий каркас (layout)

**Шапка:** логотип, меню (События, Новости, Федерация, Магазин, Поддержать), переключатель языка, кнопки «Войти» / «Вступить» (гость) или аватар с меню (вошедший: Кабинет, Выйти; для editor, moderator, admin ещё «Админка»).
**Подвал:** контакты, соцсети, реквизиты, ссылки на страницы («О федерации», «Правила», «Политика конфиденциальности»), переключатель языка. Источник: `site_settings` (`contacts`, `socials`, `footer`, `requisites`).
**Баннер статуса:** если у вошедшего участника членство истекло или скоро истекает, показывается мягкое напоминание с кнопкой «Продлить» (условия из `03`, раздел 2). Если email не подтверждён, предложение подтвердить.
**Уведомления об операциях:** короткие сообщения после действий (успех, ошибка).

## 4. Публичные страницы

### 4.1 Главная `/`
Разделы сверху вниз:

| Блок | Содержимое | Источник данных |
|---|---|---|
| Hero | Один или несколько сменяемых блоков (событие, презентация, видео, персона) | `hero_blocks`: активные, в периоде показа, по `sort_order` (`03`, раздел 11). Запасной вариант: ближайшее событие, иначе общий баннер |
| Ближайшие события | 3 карточки: обложка, дата, место, статус регистрации | `events` (`published`, начало в будущем) |
| О федерации | Короткий текст и кнопка «Вступить» | `pages` (`about` короткий фрагмент) или `site_settings` |
| Новости | 3 последних | `posts` |
| Как это работает | Шаги: вступить → тренироваться → сдать экзамен → получить баллы | статический текст через переводы |
| Магазин | 3–4 товара | `shop_items` (опубликованные) |
| Поддержать | Блок с призывом к донату | `donation_purposes` |
| Призыв | «Вступить» / «Войти» | — |

Если блока нет данных (нет событий и т. д.), он не показывается.

### 4.2 События `/events`
- Список карточек: обложка, название, дата и время, город, цена или «Бесплатно», индикатор мест («Осталось N» / «Мест нет» / «Регистрация закрыта»).
- Фильтры: город, период, цена (платные / бесплатные), дисциплина (по категориям события).
- Сортировка по дате (по возрастанию для предстоящих).
- Ссылка на архив `/events/archive`.
- Источник: `events` (`published`, `starts_at >= now`; в архиве `finished`).

### 4.3 Событие `/events/{slug}`
Содержимое: обложка, название, даты, место и карта (по координатам), описание, цена, список категорий (возраст, дисциплина, лимит), блок регистрации, поделиться (ссылка).
Результаты (для `finished`): таблица призовых мест с именами (по правилам приватности).

**Состояния блока регистрации** (определяет кнопку):

| Ситуация | Что видит пользователь |
|---|---|
| Гость | «Войдите, чтобы зарегистрироваться» |
| Нет подтверждённого email | «Подтвердите email» |
| Нет активного членства | «Для участия нужно членство» + кнопка оплаты взноса |
| Младше 18, нет согласия | «Нужно согласие родителя» + ссылка на `/cabinet/documents` |
| Возраст не подходит ни под одну категорию | сообщение с причиной |
| Окно регистрации не началось / закрыто | «Откроется ...» / «Регистрация закрыта» |
| Мест нет | «Встать в очередь» (статус `waitlist`) |
| Уже зарегистрирован | «Вы зарегистрированы» + «Отменить регистрацию» (если срок позволяет) |
| Платное, не оплачено | «Оплатить участие» с оставшимся временем удержания места |
| Можно регистрироваться | Выбор категории (если есть) и «Зарегистрироваться» |

Состояние вычисляет один серверный сервис регистраций; та же проверка повторяется в form action при отправке (кнопка — не защита).
Источник: `events`, `event_categories`, `event_registrations` (для вошедшего), `memberships`, `consents`. Условия строго по `03`, раздел 7.
SEO: `Event` микроразметка (schema.org), Open Graph с обложкой.

### 4.4 Новости `/news` и `/news/{slug}`
Список: карточки с обложкой, заголовком, кратким текстом, датой, тегами; фильтр по тегу; постраничная навигация (12 на страницу).
Страница: заголовок, дата, обложка, текст из редактора (HTML очищен при сохранении), теги, «Поделиться», блок «Читайте также» (2–3 последние новости).
Источник: `posts`. SEO: `Article` микроразметка.

### 4.5 О федерации и страницы `/federation`, `/pages/{slug}`
Отображают содержимое таблицы `pages` (заголовок и текст из редактора). Системные страницы создаются seed-скриптом: `about`, `rules`, `contacts`, `privacy`. Страница «Контакты» дополнительно показывает данные из `site_settings` (контакты, соцсети, карта).

### 4.6 Тренеры и судьи `/federation/team`
Две секции: тренеры и судьи. Карточка: фото, имя, категория, краткое описание.
Источник: `staff_profiles` с `is_public = true` и `is_active = true`, связанные пользователи не заблокированы; для несовершеннолетних фото и описание только при согласии `privacy`.

### 4.7 Магазин `/shop` и `/shop/{slug}`
Каталог: карточки с фото, названием, ценой в баллах, пометкой «Нет в наличии».
Товар: галерея, описание, выбор варианта (размер и т. п.), цена в баллах, кнопка.
Кнопка зависит от пользователя:

| Ситуация | Кнопка |
|---|---|
| Гость | «Войдите, чтобы заказать» |
| Недостаточно баллов | «Не хватает N баллов» (неактивна) |
| Нет в наличии | «Нет в наличии» |
| Можно заказать | «Заказать за N баллов» → шаг подтверждения с данными доставки |

Оформление: форма доставки (получатель, телефон, город, адрес, комментарий), экран подтверждения, затем `/cabinet/orders`. Транзакция по `03`, раздел 9.
Источник: `shop_items`, баланс из `users.points_balance`.

### 4.8 Донат `/donate`
Форма: сумма (быстрый выбор и своя), валюта, назначение (из `donation_purposes`), имя и email (для гостя; для вошедшего подставляются), чекбокс «Не показывать моё имя публично».
После отправки переход к оплате (`07-PAYMENTS.md`). Страница возврата показывает благодарность.
Опционально: публичный список последних донатов (имя и сумма), если не `is_anonymous`. Включается настройкой `feature_flags`.

### 4.9 Вступить `/join`
Описание членства: что даёт, размер взноса и срок (из `site_settings.membership_fee`), порядок вступления, ответы на частые вопросы.
Кнопка: гость → регистрация, вошедший без членства → оплата взноса, вошедший с членством → «Вы уже в федерации» и ссылка на кабинет.

### 4.10 Проверка сертификата `/certificate/{public_token}`
Показывает: имя владельца, тип и уровень, номер, дату выдачи, срок, статус («Действителен» / «Истёк» / «Отозван»). Контакты и дату рождения не показывает. Для несовершеннолетних имя и фамилия. Если токена нет, 404. Страница не индексируется поисковиками (`noindex`).

### 4.12 Проверка книжки волонтёра `/volunteer/{public_token}` (этап 10)
Логика — `03` раздел 19.2–19.4. QR в PDF и кабинете ведёт на армянскую версию (`/hy/volunteer/{token}`) — её открывают кассиры; переключатель языка есть.
- Книжка действительна: ✅, фото, имя и фамилия, номер, «Действительна до …»; ниже — видимые партнёры с логотипом и их плюшки (название, условия).
- Недействительна (членство кончилось, отозвана, не выдана, владелец заблокирован или удалён): ❌ «Книжка недействительна» и номер; без фото, причины и партнёров. Неизвестный токен — 404.
- Не показывает: контакты, дату рождения, баллы, историю, причину отзыва.
- **Кассир партнёра** (на телефоне действующий доступ, `04` раздел 2): над списком — «Вы — {партнёр}, {подпись доступа}»; у плюшек своего партнёра — остаток у разовых и кнопка «Отметить» (форма без JavaScript, подтверждение — второй кнопкой), после отметки — «Отмечено в {время}». Отказ (`03` 19.4 п. 4) — понятный текст. Чужие партнёры — без кнопок.
- `cache-control: no-store` (отзыв и отметки видны сразу), `noindex`.

### 4.13 Кассир партнёра `/partner/join/{token}`, `/partner` (этап 10)
- `/partner/join/{token}`: ссылка действует и не использована — телефон привязывается (`03` 19.4 п. 1), переход на `/partner`. Использована, просрочена, отключена или неизвестна — одна общая страница «Ссылка недействительна, попросите у федерации новую» (без подробностей).
- `/partner`: привязан — «Телефон привязан: {партнёр}, {подпись}» и подсказка «Сканируйте QR книжки камерой телефона; страница должна открыться в этом браузере». Не привязан или доступ отключён — «Телефон не привязан».
- `noindex`, `no-store`.

### 4.11 Вход и регистрация
- **Регистрация** `/register`: email, пароль (с подсказкой требований), имя, фамилия, дата рождения, согласие с политикой конфиденциальности и правилами. Если пользователю меньше 18, форма требует данные родителя (имя, телефон, email). После отправки письмо подтверждения.
- **Вход** `/login`: email, пароль, «Забыли пароль?». Ограничение попыток. Вход через Google включается по решению владельца (`01-STACK.md`, открытые решения).
- **Сброс пароля:** запрос письма, страница нового пароля по токену.
- После входа переход на запрошенную ранее страницу или `/cabinet`. Адрес возврата — только внутренний путь сайта (защита от открытого редиректа).

## 5. Личный кабинет

Общее: левое меню (на телефоне нижняя панель или раскрывающееся меню), данные только текущего пользователя (идентификатор берётся из сессии, `04`, раздел 5.3).

### 5.1 Обзор `/cabinet`
| Блок | Содержимое | Источник |
|---|---|---|
| Приветствие | имя, степень, аватар | `users` |
| Членство | статус и дата окончания, кнопка «Продлить» | `memberships` |
| Баллы | баланс и ссылка на журнал | `users.points_balance` |
| Ближайшие события | мои предстоящие регистрации | `event_registrations` |
| Что требует действия | неоплаченная регистрация, нет согласия, истекает членство, не подтверждён email | сводка из сервисов |
| Прогресс | текущая степень и следующий шаг (какой экзамен доступен) | `users.level`, `exams` |

### 5.2 Профиль `/cabinet/profile`
Редактирование: имя, фамилия, дата рождения (см. ограничение ниже), телефон, страна, город, фото, о себе, язык интерфейса, данные родителя (для несовершеннолетних). Смена email (с подтверждением) и пароля. Раздел «Приватность»: показывать ли город и фото публично.
Ограничение: дату рождения участник меняет только через обращение к админу (влияет на возрастные ограничения).
Удаление аккаунта: запрос на удаление (обрабатывает админ), мягкое удаление по `03`, раздел 1.

### 5.3 Членство `/cabinet/membership`
Статус, период действия, история членств, кнопка оплаты или продления (переход к оплате, `07-PAYMENTS.md`). Если оплата в ожидании, статус «Ожидаем подтверждение платежа».

### 5.4 Мои события `/cabinet/events`
Две вкладки: «Предстоящие» и «Прошедшие».
Предстоящие: событие, дата, категория, статус регистрации, кнопки «Оплатить» и «Отменить» по условиям.
Прошедшие: событие, итоговое место, оценка, начисленные баллы (по журналу).

### 5.5 Прогресс `/cabinet/progress`
- Шкала степеней (новичок → продвинутый → профи) с отметкой текущей.
- Экзамены: назначенные и пройденные (дата, результат).
- Сертификаты: список (тип, номер, дата, срок, статус), скачать PDF, копировать ссылку проверки, QR-код.
- Если профиль тренера или судьи активен: блок «Мой профиль тренера / судьи» с настройкой публичности.
Источник: `exams`, `certificates`, `staff_profiles`.

### 5.6 Баллы `/cabinet/points`
Баланс, журнал начислений (дата, причина, источник, сумма, комментарий), фильтр по периоду и причине, подсказка «как заработать баллы» (по активным правилам `points_rules`, с актуальными значениями) и ссылка в магазин.
Источник: `points_ledger`, `points_rules`.

### 5.7 Видеоистория `/cabinet/videos`
Форма добавления: ссылка, название, событие (необязательно). Проверка платформы и дублей. Список видео со статусом (на проверке, одобрено, отклонено с причиной) и пометкой начисленных баллов. Видео можно удалить, пока оно не одобрено.
Источник: `videos`.

### 5.8 Заказы `/cabinet/orders`
Список заказов: номер, состав, сумма, статус, дата. Карточка: данные доставки, трек-заметка. Кнопка «Отменить» пока заказ не отправлен.
Источник: `shop_orders`, `shop_order_items`.

### 5.9 Платежи `/cabinet/payments`
История платежей (взносы, донаты, оплата участия): дата, тип, сумма, статус, квитанция.
Источник: `payments`.

### 5.10 Документы `/cabinet/documents`
Согласия и документы: согласие родителя, медицинский допуск, согласие на публикацию фото и видео. Для каждого: статус, срок, загрузка скана или фото, причина отказа при отклонении. Подсказка, что нужно для регистрации на события.
Источник: `consents`. Файлы — личные данные: загрузка и просмотр только по временной подписанной ссылке.

### 5.11 Обучение `/cabinet/training` (этап 9)
Логика — `03` раздел 18. Портал живёт внутри кабинета: тот же вход, отдельного пароля нет; всё проверяется на сервере по заявке участника.

**Список курсов** `/cabinet/training`: опубликованные курсы. По каждому — описание и состояние:
- условия не выполнены — какие (членство, возраст, степень), кнопки нет;
- можно подать — кнопка «Запросить доступ»;
- `pending` — «Заявка на рассмотрении»;
- `rejected` / `revoked` — причина и кнопка «Подать снова» (для `rejected`);
- `approved` — кнопка «Открыть портал» и прогресс: тест (не сдан / сдан, дата пересдачи), практика (принято N из M);
- курс завершён — «Курс пройден, ждёт выдачи сертификата»; после выдачи — ссылка на сертификат в `/cabinet/progress`.

**Портал курса** `/cabinet/training/{course}`: темы с уроками по порядку, внизу — блоки «Тест» и «Практика» с состоянием. Урок — заголовок, текст, видео, кнопка «Скачать PDF» (подписанная ссылка).

**Тест** `/cabinet/training/{course}/test`:
- до начала — правила (вопросов, сколько нужно, минут, попыток осталось, когда можно пересдать) и кнопка «Начать»; кнопки нет, если нельзя (с причиной);
- во время — все вопросы на одной странице, по одному варианту на вопрос, таймер; ответы сохраняются на сервере по ходу (форма работает и без JavaScript — отправка в конце); кнопка «Завершить» с подтверждением;
- после — правильных X из Y, сдал / не сдал, когда можно пересдать. Правильные ответы не показываются.
- История попыток: дата, результат.

**Практика** `/cabinet/training/{course}/practice`: до сданного теста — список заданий без формы. После — по каждому заданию описание и критерии, поле ссылки (YouTube или Google Drive) с подсказкой «загрузите ролик с доступом по ссылке», статус (на проверке / принято / вернули с комментарием), история отправок.

**Обзор** `/cabinet` («Что требует действия»): заявка одобрена — «Открыть портал»; видео вернули — «Переснимите задание».

### 5.12 Волонтёрство `/cabinet/volunteer` (этап 10)
Логика — `03` раздел 19. Одна страница, блоки сверху вниз:

**Книжка** — состояние:
- условия не выполнены — каких не хватает (email, членство, фото профиля, до 18 — согласие `privacy` со ссылкой на `/cabinet/documents`), кнопки нет;
- можно подать — короткое описание (что даёт книжка, что фото и имя видны по QR) и кнопка «Запросить книжку»;
- `pending` — «Заявка на рассмотрении»;
- `rejected` / `revoked` — причина и кнопка «Подать снова»;
- `active` и действительна — номер, «Действительна до …», QR (тот же адрес, что в PDF), «Скачать PDF»;
- `active`, но недействительна — почему (членство кончилось — кнопка «Продлить»); PDF и QR не показываются.

**Плюшки** (книжка действительна): видимые партнёры и плюшки, у разовых — остаток. **Мои использования**: дата, партнёр, плюшка; отменённые — с пометкой «отменено».

**Приглашения**: открытые — запрос (название, время, место, событие), мест осталось, срок ответа, кнопки «Пойду» / «Не могу» (можно передумать до срока); прошедшие — ответ и явка. У `attended` — форма фотоотчёта (фото или ссылка, комментарий) и его статус (на проверке / принят, начислено N баллов / вернули с комментарием).

**Предупреждение**: при пометке об отказах (`03` 19.6) — плашка над всеми блоками: сколько отказов подряд и что решение о книжке принимает федерация.

**Обзор** `/cabinet` («Что требует действия»): приглашение без ответа (со сроком), фотоотчёт вернули, предупреждение об отказах.

## 6. Системные письма и ссылки в них
Письма ведут на страницы сайта по полному адресу `PUBLIC_SITE_URL`:
- подтверждение email → `/verify-email?token=...`
- сброс пароля → `/reset-password?token=...`
- событие, оплата, заказ → страницы кабинета
- сертификат → `/cabinet/progress` и `/certificate/{token}`
- обучение (заявка, тест, практика, курс пройден) → `/cabinet/training` и страницы курса; админу — `/admin/training/access` и `/admin/training/practice`
- волонтёрство (книжка, приглашение, отмена запроса, предупреждение, фотоотчёт) → `/cabinet/volunteer`; админу (новая заявка) — `/admin/volunteer/cards`

Список писем: `03`, раздел 14.

## 7. SEO и доступность

1. У каждой публичной страницы: `title`, `description`, Open Graph (изображение), канонический URL.
2. `sitemap.xml` генерируется из событий, новостей, страниц, товаров. `robots.txt`: закрыты `/cabinet`, `/admin`, `/api`, `/certificate`, `/volunteer`, `/partner`.
3. Микроразметка: `Event`, `Article`, `Organization`, `Product` (товары).
4. Для многоязычности теги `hreflang` для включённых языков.
5. Изображения: `alt` из медиатеки, адаптивные размеры, ленивая загрузка (кроме первого экрана).
6. Доступность: семантическая разметка, видимый фокус, контраст по WCAG AA, управление с клавиатуры, подписи к полям форм.

## 8. Производительность

1. Цель: быстрая первая отрисовка на мобильных устройствах (большая часть аудитории — подростки с телефонов).
2. Публичные страницы с редко меняющимся содержимым (главная, события, новости, страницы) кешируются с коротким временем жизни. Кеш сбрасывается при изменении данных из админки.
3. Изображения: современные форматы (WebP или AVIF), несколько размеров, размеры заданы заранее, чтобы страница не «прыгала».
4. Тяжёлые библиотеки (редактор, карты) подгружаются только там, где нужны. Карта событий загружается по нажатию.
5. Видео не хранится на сайте, только встраивание по ссылке и загрузка по клику (предварительная заставка).

## 9. Состояния и ошибки
- Пустые списки: понятный текст («Событий пока нет») без пустой страницы.
- Загрузка: индикатор при действиях, кнопки блокируются от двойной отправки.
- Ошибки форм: у поля, сообщение понятным языком, введённые значения сохраняются.
- Ошибки сервера: общая страница 500 без технических деталей, подробности в логе.
- 404 для несуществующих и недоступных чужих ресурсов (`04`, раздел 5.4).
- Если оплата не прошла, пользователь видит причину и кнопку «Попробовать снова».
