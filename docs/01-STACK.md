# 01-STACK: Технологии и структура проекта

> Отвечает на вопросы: какой стек, где что лежит, как слои связаны, какие команды и переменные.
> Правила работы агента — `.cursor/rules/main.mdc`. Структура таблиц — только в `02-DATABASE.md`.
>
> **Статус: предварительно.** Структура папок может меняться. Меняет её только владелец; агент предлагает изменение и ждёт «go», а не переделывает сам.

## Принципы
- Один монолит на SvelteKit: публичный сайт, личный кабинет, админка и API в одном приложении.
- Минимум зависимостей. Новую библиотеку добавлять только по согласованию (см. «Нельзя» в правилах).
- Всё строго типизировано (TypeScript strict).
- Версии фиксируются в `package.json` и lock-файле. Использовать актуальные стабильные версии на момент установки, не менять мажорные версии без просьбы.

## Технологии

| Слой | Выбор | Зачем |
|---|---|---|
| Фреймворк | SvelteKit + Svelte 5 (runes) | Сайт, админка, API, form actions |
| Язык | TypeScript (strict) | Безопасность типов |
| База данных | PostgreSQL | Основное хранилище |
| ORM и миграции | Drizzle ORM + drizzle-kit | Схема в коде, миграции из схемы |
| Авторизация | Better Auth | Email и пароль, сессии, роли. Lucia не использовать (проект свёрнут) |
| Валидация | Zod | Проверка всех входных данных на сервере |
| Стили | Tailwind CSS | Быстрая вёрстка, дизайн-токены в `08-DESIGN.md` |
| Редактор текста | TipTap | Новости и описания в админке без кода |
| Файлы | Cloudflare R2 (S3-совместимое) через AWS SDK v3 | Обложки, фото, PDF сертификатов |
| Почта | Resend (или аналог, см. открытые решения) | Письма: регистрация, оплата, сертификаты |
| Платежи | Определяется в `07-PAYMENTS.md` | Взнос и донаты |
| Тесты | Vitest (логика), Playwright (ключевые сценарии) | Минимум для критичных мест: баллы, платежи, права |
| Линтинг | ESLint + Prettier | Единый стиль |

Всё, чего нет в таблице, — новая зависимость и требует согласования.

## Хостинг и деплой
- **Приложение:** VPS (Linux) в Docker, адаптер `@sveltejs/adapter-node`, обратный прокси Caddy или Nginx с автоматическим HTTPS.
- **База:** PostgreSQL на том же VPS на старте, ежедневные бэкапы с копией вне сервера. При росте переезд на управляемую базу.
- **Файлы:** Cloudflare R2, не на диске сервера.
- **Домен:** собственный домен федерации, DNS настраивается на VPS. Все ссылки и письма используют `PUBLIC_SITE_URL`.
- **Окружения:** `development` (локально), `production`. Отдельный `staging` по желанию позже.
- **Деплой:** сборка Docker-образа, запуск миграций перед стартом новой версии. Деплой — только по просьбе владельца.

## Структура папок (предварительно)
```
/
├─ .cursor/rules/main.mdc        правила агента
├─ docs/                         документация проекта (00–09, PROGRESS)
├─ drizzle/                      сгенерированные миграции (не править вручную)
├─ scripts/                      seed, утилиты
├─ static/                       статические файлы
├─ tests/e2e/                    сценарии Playwright
├─ src/
│  ├─ app.html, app.css
│  ├─ hooks.server.ts            сессия, проверка ролей, логирование
│  ├─ lib/
│  │  ├─ components/             UI-компоненты (общие, формы, hero-блоки)
│  │  ├─ i18n/                   файлы переводов (ru, позже hy, en)
│  │  ├─ validation/             схемы Zod
│  │  └─ server/                 только сервер, в клиент не попадает
│  │     ├─ db/                  подключение, schema/ (по сущностям)
│  │     ├─ auth/                настройка авторизации, проверка прав
│  │     ├─ services/            бизнес-логика: points, membership, events, payments, shop
│  │     ├─ storage/             работа с R2
│  │     ├─ mail/                отправка писем и шаблоны
│  │     └─ audit.ts             запись в журнал действий
│  └─ routes/
│     ├─ (site)/                 публичный сайт и личный кабинет
│     ├─ admin/                  админ-панель (доступ только по ролям)
│     └─ api/                    вебхуки платежей и внутренние эндпоинты
├─ .env.example                  список переменных без значений
├─ docker-compose.yml            локальный Postgres
├─ drizzle.config.ts
├─ svelte.config.js
├─ Dockerfile
└─ package.json
```

Новые папки верхнего уровня и новые разделы в `src/lib/server/` — только по согласованию. Без свалок `utils/`, `misc/`, `helpers/` без домена.

## Как слои связаны
- Маршрут (`+page.server.ts`, form action) принимает запрос, проверяет права, валидирует через Zod и вызывает **сервис**.
- Сервис содержит бизнес-логику и работает с БД через Drizzle. Маршруты не пишут логику начисления баллов или смены степени сами.
- Любое изменение баллов, степеней, платежей и ролей сервис пишет в `audit_log`.
- Админка и публичный сайт используют одни и те же сервисы.
- Права проверяются на сервере в каждом маршруте и в `hooks.server.ts` для `admin/`; скрытие кнопки в интерфейсе — не защита.

## Команды
| Команда | Что делает |
|---|---|
| `npm install` | Установка зависимостей |
| `npm run dev` | Локальный запуск |
| `npm run build` | Сборка |
| `npm run preview` | Проверка сборки |
| `npm run check` | Проверка типов (`svelte-check`) |
| `npm run lint` | ESLint и Prettier |
| `npm run test` | Тесты Vitest |
| `npm run test:e2e` | Тесты Playwright |
| `npm run db:generate` | Создать миграцию из изменений схемы |
| `npm run db:migrate` | Применить миграции |
| `npm run db:studio` | Drizzle Studio (просмотр данных) |
| `npm run db:seed` | Наполнить БД тестовыми данными (`scripts/seed.ts`) |

Локальная база поднимается через `docker compose up -d` (Postgres в контейнере, `docker-compose.yml` в корне).

**Проверка перед коммитом** (для отчёта «Проверка» из правил): `npm run check`, `npm run lint`, `npm run test`; для баллов, платежей и прав — плюс тесты этой зоны.

## Соглашения
- Схема БД лежит в `src/lib/server/db/schema/`, по одному файлу на группу сущностей. Источник правды по структуре: `02-DATABASE.md`.
- Миграции создаются только командой `db:generate`, руками не правятся. Перед `db:generate` и `db:migrate` — Migration Gate из правил (план + откат + «go»).
- Серверный код только в `src/lib/server/` и `+*.server.ts`.
- Unit-тесты Vitest лежат рядом с кодом: `points.ts` → `points.test.ts`.
- Загрузка файлов: клиент получает подписанную ссылку от сервера и грузит в R2 напрямую, сервер сохраняет только путь.
- Ошибки пользователю показываются понятным текстом, технические детали идут в лог.
- Размер файлов — по лимитам из правил (цель ≤ 50 строк, > 200 — сначала план сплита).

## Открытые решения (подтвердить у владельца)
1. **Хостинг:** предложен VPS с Docker. Альтернатива: Vercel или Cloudflare, но тогда меняется адаптер и подход к базе.
2. **Авторизация:** предложен Better Auth. Нужно ли сразу вход через Google?
3. **Почта:** Resend предложен как пример, провайдер можно заменить.
4. **Платежи:** провайдер не выбран. Решение фиксируется в `07-PAYMENTS.md` и определяет раздел `PAYMENT_*` в окружении.
5. **Структура папок:** предварительная, может измениться до или во время этапа 1.
