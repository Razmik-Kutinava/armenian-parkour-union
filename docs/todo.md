## Задача

4.6 Тесты: двойное начисление невозможно, отрицательный баланс невозможен, `reversal` отменяет один раз, кэш баланса совпадает с суммой журнала. REVIEW — общий в конце этапа 4 (решение владельца 2026-10-21).

Уже покрыто (4.1, 4.3): последовательные повторы в одной транзакции (`award` / `adjust` / `reverse.test.ts`), запреты базы (`points-schema.test.ts`: уникальные индексы, append-only; `schema.test.ts`: `points_balance >= 0`). Не покрыто — **гонки** (два соединения одновременно) и сквозная сверка «баланс = сумма журнала» после каждой операции, включая отказы.

- Гонки — на ядре `appendEntry` (единственный писатель журнала), два соединения; второе ждёт блокировку строки пользователя (видно в `pg_stat_activity`), затем первое коммитит. Ожидание: один источник — одна запись (второй `duplicate`); два списания сверх баланса — второе `insufficient_balance` без исключения (без блокировки строки — падение `CHECK` или уход в минус); две отмены одной записи — вторая `duplicate`; баланс = сумма журнала.
- Второе соединение видит только закоммиченное: гонкам нужны закоммиченные строки. Записи журнала удалить нельзя (append-only), поэтому тест оставляет на запуск 4 пользователя `t-race-*@example.com` (после теста — `deleted_at`) и 8 записей журнала; в CI база временная. Правила баллов и журнал действий не коммитятся.
- Четвёртая гонка: два разных начисления сразу — оба записаны, «баланс до» второго = «после» первого, баланс = сумма.
- Сквозной сценарий (в откате): начисления по правилам, повтор источника, ручные ±, отказ ниже нуля, отмена, повторная отмена, отмена отмены, отмена ниже нуля — после каждого шага баланс ≥ 0 и равен сумме журнала.
- Сверка по всей базе — нет: e2e-фикстуры пишут баланс и журнал SQL-ом напрямую.
