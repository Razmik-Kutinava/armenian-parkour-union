# Проверка этапов владельцем

> Чек-лист на ~10 минут на этап: действие → что должно получиться. Проверять на проде https://parkour.am (этап должен быть выкатан).
> Тестовый участник — второй email владельца, в окне инкогнито; админ — свой аккаунт. Тестовые данные на проде после проверки скрыть (удаление мягкое).
> Всё совпало — написать агенту «этап N ок»: статус в `PROGRESS.md` → `закрыт`. Не совпало — номер пункта и что видно: агент чинит через `/patch`.
> Новый раздел пишет агент в `/review` этапа (по «Готово, когда» этапа в `09`), не больше 12 пунктов, плюс «Не проверено агентом» — что агент проверить не смог, почему и кто делает.
> Пока этап ждёт проверки, задачи следующих этапов идут дальше — проверка их не блокирует.

## Этап 1. Каркас

1. Главная на телефоне: шапка, подвал, переключатель языка; `/hy` и `/ru` — интерфейс на армянском и русском.
2. Инкогнито → `/register` вторым email (дата рождения до 18 → просит данные родителя) → письмо подтверждения приходит, ссылка подтверждает.
3. Выйти → `/login` с неверным паролем несколько раз подряд → сообщение об ограничении попыток.
4. `/forgot-password` → письмо приходит во входящие → новый пароль работает.
5. Вход через Google своим аккаунтом → попадаешь в `/cabinet`.
6. `/admin/users/new` — создать пользователя; `/admin/users` — тестовому участнику роль «редактор» → у него в `/admin` только разрешённые разделы, `/admin/users` — 403.
7. Заблокировать тестового участника → в его вкладке после обновления он гость.
8. `/admin/roles` — снять роль админа с себя → отказ.
9. `/admin/audit` — видны создание, смена роли, блокировка из пунктов 6–7.
10. Несуществующий адрес (`/xyz`) → страница 404 сайта.

**Не проверено агентом:** вход через Google до конца (нужен живой аккаунт — владелец, пункт 5); письмо сброса пароля во входящих (живая почта — владелец, пункт 4); письмо «задайте пароль» из админки уходит на языке админа (известно, не баг теста).

## Этап 2. Контент

1. `/admin/media` — загрузить картинку с alt → есть в медиатеке.
2. `/admin/news/new` — черновик с этой обложкой → в инкогнито на `/news` его нет; опубликовать → есть; дата публикации завтра → нет.
3. `/admin/events/new` — событие с обложкой, опубликовать → есть на `/events` и своей странице; «Дублировать» → копия-черновик.
4. `/admin/hero` — блок с этим событием первым → на главной; снять событие с публикации → блок пропал, показан запасной.
5. Удалить в `/admin/media` картинку, которая стоит обложкой → отказ «используется».
6. Новость заполнить только на EN → на `/ru/news/…` текст на английском.
7. Изменить заголовок опубликованной новости → на сайте новый сразу после сохранения.
8. `/pages/about`, `/pages/privacy`, `/pages/contacts` открываются на трёх языках.
9. `/sitemap.xml` и `/robots.txt` открываются; ссылка на новость в Telegram → превью с картинкой.
10. Главная, `/events`, `/news` на телефоне открываются быстро, вёрстка не едет.

**Не проверено агентом:** загрузка в настоящий R2 через `/admin/media` в браузере (в CI бакета нет — владелец, пункт 1); тексты `privacy` / `offer` / `refund-policy` (юрист); армянский перевод (носитель языка); фото сайта — заглушки CC0 (нужны настоящие от владельца); у почты домена нет DMARC (письма могут уходить в спам — владелец в DNS).

## Этап 3. Членство и платежи (без онлайн-оплаты — она после 3.13)

1. `/join` — взнос 1000 AMD / 12 мес., кнопка «Онлайн-оплата сейчас недоступна».
2. `/admin/payments/new` — ручной платёж взноса тестовому участнику → подтвердить → у него `/cabinet/membership` — членство активно до даты через 12 мес., письмо об оплате пришло.
3. Тестовый участник: `/cabinet/payments` — платёж виден, карточка открывается.
4. `/admin/payments` — карточка платежа, фильтр «требуют проверки», выгрузка CSV открывается.
5. `/admin/settings/payments` — размер взноса и лимиты донатов видны, сохранение пишет `settings.update` в `/admin/audit`.
6. `/donate` в инкогнито — форма есть, онлайн-оплата недоступна.

**Не проверено агентом:** оплата картой — на Fly нет секретов `PAYMENT_*` (после счёта НКО и эквайринга — владелец); 3.13 VPOS.am — песочница и боевая проверка малой суммой (нужны доступы); ответ VPOS, в чём `amountMinor` для AMD (в коде × 100 — владелец спрашивает VPOS); на проде пусты `contacts`, `socials`, `requisites` в `/admin/settings` (подвал без контактов, квитанции без реквизитов — владелец).

## Этап 4. Баллы

1. `/admin/point-rules` — правила с суммами есть.
2. `/admin/points/new` — начислить тестовому участнику 10 баллов с комментарием → в журнале `/admin/points` запись.
3. Тестовый участник: `/cabinet/points` — баланс 10, запись с комментарием, блок «как заработать».
4. Списать больше, чем на балансе → отказ.
5. Отменить запись из пункта 2 → баланс 0; отменить её же ещё раз → отказ.
6. Модератор (роль тестовому участнику) открывает `/admin/point-rules` — только чтение.
7. `/admin/audit` — `points.adjust` и `points.reverse` видны.

**Не проверено агентом:** нет — всё покрыто тестами; ручная проверка — пункты выше.

## Этап 5. Регистрации и кабинет

Перед проверкой: тестовому участнику — активное членство (ручной платёж взноса, этап 3, п. 2) и дата рождения взрослого. Платное событие на проде не проверить — онлайн-оплаты нет (этап 3).

1. `/admin/events/new` — бесплатное событие через неделю, лимит 1, категории «Взрослые» (от 18) и «Дети» (до 14), опубликовать.
2. Тестовый участник: страница события → категории только «Взрослые» → «Зарегистрироваться» → «Вы зарегистрированы», письмо «зарегистрированы» пришло, в `/cabinet/points` — баллы за регистрацию.
3. Второй участник (или свой аккаунт с членством) — то же событие → «Мест нет, встать в очередь» → в очереди, письмо об очереди.
4. Тестовый участник: `/cabinet/events` — событие в «Предстоящих», «Отменить» → второй из очереди стал зарегистрирован, ему письмо «место освободилось»; баллы тестового за регистрацию сняты обратной записью.
5. `/admin/registrations` → событие → список с числами; «Добавить участника» по email; CSV открывается.
6. Участник до 18 лет (дата рождения в профиле) на странице события → «Нужно согласие родителя» со ссылкой в `/cabinet/documents`.
7. `/admin/consents` — список открывается (загрузку на проде не проверить — п. «Не проверено»).
8. В день события (или поставить начало на сегодня): `/admin/registrations/<событие>/day` **с телефона** → поиск по имени, «Пришёл» → баллы за участие у участника.
9. «Результаты» → место 1 → у участника баллы за победу; сохранить ещё раз → баллы не удвоились; «Завершить» — событие в архиве.
10. Другое событие с регистрациями → «Отменить событие» → всем письмо об отмене, в `/cabinet/events` — «Событие отменено»; удалить событие с регистрациями → отказ.
11. Модератор (роль тестовому) в `/admin/registrations/<событие>` — имена и возраст без email; «Завершить» — недоступно.
12. `/admin/audit` — `registration.*`, `event.cancel`, `consent.*` видны.

**Не проверено агентом:** загрузка согласия и просмотр файла — на Fly нет `R2_PRIVATE_BUCKET` (владелец: приватный бакет R2 без публичного домена, CORS PUT с `parkour.am`, доступ токену, секрет на Fly — до этого несовершеннолетние не могут зарегистрироваться); платное участие, удержание места и поздняя оплата — только тестами (на проде нет онлайн-оплаты, 3.13); живая доставка писем этапа (Resend) — владелец по пп. 2–4, 10; «День события» на настоящем телефоне — владелец, п. 8; одновременные нажатия — только тестами (5.10).
