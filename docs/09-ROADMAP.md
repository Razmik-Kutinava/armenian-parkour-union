# 09-ROADMAP: Порядок сборки

> Отвечает на вопросы: в каком порядке строим сайт, что входит в каждый этап, что читать, когда этап готов.
> Правила работы агента — `.cursor/rules/main.mdc`. Текущее состояние — `docs/PROGRESS.md`.

Агент работает **по одному этапу за раз** (правило из `.cursor/rules/main.mdc`).

**Почему такой порядок:** регистрация на событие требует активного членства, значит платежи и членство готовы раньше регистраций. Баллы начисляются за регистрацию и участие, значит ядро баллов тоже раньше регистраций. Итог: контент → членство и платежи → баллы → регистрации → сертификаты → видео и магазин.

## 0. Как пользоваться

1. Этап берётся целиком в работу только после завершения предыдущего (исключения указаны в «Зависимости»).
2. Внутри этапа задачи пронумерованы (`1.1`, `1.2`...). Одна сессия Cursor = одна или несколько соседних задач, не весь этап сразу.
3. В начале сессии агент читает `PROGRESS.md` и документы из строки «Читать» этапа.
4. В конце сессии агент отмечает выполненные задачи в `PROGRESS.md` (раздел «Сделано»), делает коммит и пишет отчёт по шаблону из правил (Сделано / Не сделано / Проверка / Как проверить руками / Открытые вопросы / Коммит).
5. Этап считается закрытым, когда выполнен чек-лист «Готово, когда» и владелец проверил результат руками.
6. Размер этапа: **S** (до 2–3 сессий), **M** (4–7), **L** (8 и больше). Это ориентир, а не обещание сроков.
7. Перед задачей проверить «Открытые вопросы» в `PROGRESS.md`: если вопрос блокирует задачу — стоп и вопрос владельцу.

### Общее определение «готово» для любой задачи
- Код проходит `npm run check` и `npm run lint` без ошибок.
- Для критичной логики (баллы, платежи, права, статусы) написаны тесты (`03`, `04`, `07`).
- У каждой новой сущности есть раздел админки по `05-ADMIN-PANEL.md`.
- Права проверены на сервере по `04-ROLES-PERMISSIONS.md`.
- Опасные действия пишутся в `audit_log`.
- Значения правил берутся из БД, а не из кода.
- Схема БД совпадает с `02-DATABASE.md` (изменения схемы — только через Migration Gate из правил и с правкой `02`).
- Seed-скрипт обновлён, если нужны новые начальные данные.
- Компоненты соответствуют `08-DESIGN.md`, тексты через файлы переводов.
- `PROGRESS.md` обновлён, коммит сделан.

## 1. Обзор этапов

| Этап | Название | Размер | Главный результат |
|---|---|---|---|
| 0 | Подготовка | S | Репозиторий, окружения, домен, хостинг, база, CI |
| 1 | Каркас | L | Вход, роли, оболочка админки, пользователи, журнал действий, дизайн-токены |
| 2 | Контент | L | События, hero-блоки, новости, страницы, медиа, настройки (публично и в админке) |
| 3 | Членство и платежи | L | Оплата взноса и донаты, ручные платежи, сверка |
| 4 | Баллы (ядро) | M | Журнал, правила, сервис начисления, ручная корректировка |
| 5 | Регистрации и кабинет | L | Регистрация на события, согласия, «День события», результаты, личный кабинет |
| 6 | Экзамены и сертификаты | L | Степени, сертификаты (PDF, QR), тренеры и судьи |
| 7 | Видео и магазин | M | Видеоистория с модерацией, магазин за баллы, заказы |
| 8 | Доводка и запуск | L | Дашборд, письма, SEO, скорость, безопасность, бэкапы, запуск |
| 9 | После MVP | — | Список идей (раздел 11) |

Критический путь к минимальному запуску (если нужно срочно показать сайт): этапы 0, 1, 2, затем 8 в сокращённом виде. Остальное подключается по мере готовности.

## 9. Как формулировать задачу для Cursor

Шаблон (подставить номер этапа и задач):

```
Реализуй задачи 2.1–2.3 из docs/09-ROADMAP.md.
Сначала прочитай docs/PROGRESS.md, 00-PROJECT.md и документы из строки «Читать» этапа 2.
Делай только эти задачи, дальше не иди.
Если чего-то не хватает или документы противоречат друг другу, остановись и спроси.
В конце обнови docs/PROGRESS.md, сделай коммит и напиши отчёт: Сделано / Не сделано / как проверить вручную.
```

Правила:
- Одна сессия: 1–4 соседние задачи.
- Если агент предлагает сменить стек, структуру или схему БД, сначала согласовывается документ, потом код.
- После каждого этапа: владелец проверяет руками, затем ветка `dev` вливается в `main` (push и слияние — по команде владельца).

## 11. После MVP (идеи, не брать в работу без решения)

- Двухфакторная защита для админов.
- Тёмный режим.
- Рейтинги и сезонные таблицы, расширенная статистика.

- Судейские листы и подсчёт оценок по попыткам.
- Офлайн-режим для «Дня события».
- Мобильное приложение или PWA с уведомлениями.
- Telegram-уведомления участникам.
- Публичные профили участников и галереи (только с учётом согласий).
- Второй платёжный провайдер (Idram и др.).
- Карта паркур-площадок Армении.
